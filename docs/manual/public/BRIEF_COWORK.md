# Brief สำหรับ Claude Cowork: คู่มือการใช้งานหน้าเว็บ SEA-HAF ฉบับประชาชน

## งาน

เรียบเรียง**คู่มือการใช้งานหน้าเว็บ SEA-HAF สำหรับประชาชนทั่วไป** จากไฟล์ในโฟลเดอร์นี้
ผู้อ่านคือคนทั่วไป ครู เจ้าหน้าที่ท้องถิ่น และสื่อมวลชน ซึ่งไม่ใช่นักพัฒนาหรือนักวิจัย

- **ความยาว:** ประมาณ 25–40 หน้า
- **ภาษา:** ไทยเป็นหลัก ใช้ชื่อปุ่มตามที่หน้าเว็บแสดง และวงเล็บภาษาอังกฤษเมื่อหน้าเว็บมีทั้งสองภาษา
- **ไฟล์ที่ต้องส่ง:** Word และ PDF ใช้ฟอนต์ Sarabun และใส่คำบรรยาย "รูปที่ n …" ใต้ภาพทุกภาพ

หน้าเว็บ:

| ที่อยู่ | คำอธิบาย |
|---|---|
| <https://sea-haf.pages.dev> | หน้าหลัก |
| `/classic.html` | หน้าแบบเดิม |

## สิ่งที่ตัดออกจากคู่มือฉบับเต็มแล้ว

ส่วนเหล่านี้ไม่ต้องนำกลับมา:

- **บทที่ 1–3 (methodology) ทั้งหมด** ยกเว้นข้อความที่คัดไว้ใน `02_sources.md` สิ่งที่ตัดออกได้แก่:
  - สมการ Kalman, regression kriging, ML v1/v2, hindcast expert, nowcast และแบบจำลองควันไฟ
  - การทำงานของ GitHub Actions และ state ของระบบ
- **บทที่ 4 (model evaluation)** ยกเว้นตารางหลัก B.3.1 และข้อจำกัด B.10 สิ่งที่ตัดออกได้แก่:
  - การเทียบ CAMS กับ SILAM
  - ML v2 และ hindcast
  - ฝนเทียบกับเรดาร์
  - กรณีศึกษา และสคริปต์สร้างรูป
- **บทที่ 6–7** ทั้งหมด ได้แก่ การติดตั้ง ชื่อ secret ตารางค่าตั้ง โมดูล ไฟล์ผลลัพธ์ การ deploy และการแก้ปัญหาของผู้ดูแล
- **บทที่ 8 บางส่วน:** ตัดรายการตัวแปรและประวัติการเปลี่ยนแปลงออก แต่เก็บอภิธานศัพท์และการอ้างอิงข้อมูลไว้ใน `02_sources.md`
- **ในบทหน้าเว็บ:**
  - หัวข้อ 5.4 (เลือก CAMS/SILAM ซึ่งมีเฉพาะหน้า developer)
  - หัวข้อ 5.19 (หน้า developer)
  - แถวตารางชั้นข้อมูลที่ใช้ได้เฉพาะหน้า developer
  - หมายเหตุอ้างบรรทัดโค้ด
  - ไฟล์ `ISSUES_*`

## สิ่งที่ต้องทำต่อ

1. **ลบหรือเขียนใหม่ทุกบรรทัดใน `DEV_MENTIONS.txt`** (9 บรรทัด) เช่น
   - แถว `/dev.html` ในตารางหน้าเว็บ
   - "ปุ่มกุญแจ" ให้เขียนแค่ว่าเป็นทางเข้าของผู้ดูแลระบบ
   - ประโยค "หน้า developer มี…"
   - การอ้างถึงรูปที่ C.38
2. **เรียงเลขรูปใหม่** เพราะรูปเดิม C.5, C.37 และ C.38 ถูกตัดออก และปรับการอ้างอิงหัวข้อ เช่น "หัวข้อ 5.4" และ "5.18" ให้ตรงกับเล่มใหม่
3. **เอาศัพท์โค้ดออกจากเนื้อความ**
   - เช่น `index.html`, `data/latest.json`, `syncSilamUI`, `scripts/...`, `localStorage`
   - ถ้าจำเป็นให้เขียนเป็นภาษาคน เช่น "หน้าเว็บโหลดข้อมูลรอบใหม่ทุก 3 นาที"
4. **เพิ่มบทสั้น ๆ ที่ฉบับเต็มยังไม่มี** โดยใช้ `02_sources.md`
   - "SEA-HAF คืออะไร และพยากรณ์อย่างไร" (1–2 หน้า ไม่มีสมการ)
     - อธิบายว่าเริ่มจากแบบจำลอง CAMS ของ Copernicus
     - ปรับแก้ด้วยค่าที่สถานีวัดได้ทุกชั่วโมง
     - คิดควันจากจุดความร้อนตามลม
     - ถ้าอยากใช้แผนภาพ ให้วาดใหม่แบบง่าย
   - "ข้อมูลมาจากไหน" เป็นตารางสั้นของแหล่งข้อมูล พร้อมคำขอบคุณและสัญญาอนุญาตจากหัวข้อ 8.3 ซึ่งต้องคงไว้ครบ
   - "แม่นแค่ไหน" ให้อธิบายคะแนนความแม่นยำบนหน้าเว็บ (100 − NRMSE ของค่าเฉลี่ยรายวัน 30 วัน) ด้วยภาษาง่าย
     - ยกผลหลักจากตาราง B.3.1 เป็นข้อความ เช่น "พยากรณ์ล่วงหน้า 24 ชม. คลาดเฉลี่ยประมาณ … µg/m³"
     - บอกข้อจำกัดจาก B.10 ตรง ๆ
5. **คงบท "อ่านค่าอย่างไร" และ FAQ ไว้** ปรับให้อ่านง่ายและเพิ่มคำถามที่ประชาชนน่าจะถาม เช่น
   - "ควรใส่หน้ากากเมื่อไร"
   - "ทำไมค่าบนเว็บต่างจากแอปอื่น"
   - "ค่ารอยืนยันคืออะไร"
6. **แนะนำผู้อ่านตามกลุ่ม** เช่น
   - "ถ้าอยากรู้แค่วันนี้ฝุ่นเป็นอย่างไร ดูหน้า …"
   - "ครูหรือผู้นำชุมชนที่อยากบันทึกภาพไปประกาศ ดูหัวข้อบันทึกภาพ"

## ข้อควรระวัง

- **ภาพหน้าจอใช้ข้อมูลจำลอง** ตัวเลขในภาพไม่ใช่ค่าพยากรณ์จริง ต้องคงหมายเหตุนี้ไว้ หรือถ่ายภาพใหม่จากหน้าเว็บจริงถ้าทำได้
  - ภาพชั้นฝน อุณหภูมิ และลม มีแค่ legend ควรถ่ายใหม่จากเว็บจริง
- **ห้ามใส่** รหัสผ่าน key หรือ token ห้ามอธิบายวิธีเข้าหน้า developer และห้ามใส่ชื่อ secret
- **ห้ามเขียนว่าระบบใช้ ML v2, climatology blend หรือ SILAM บนหน้าประชาชน** เพราะยังไม่ได้เปิดใช้
- **ห้ามแต่งตัวเลขความแม่นยำเอง** ใช้เฉพาะตัวเลขใน `02_sources.md` พร้อมช่วงวันที่ที่กำกับไว้
- **ห้ามแก้ repo หรือ push** งานนี้ทำในโฟลเดอร์ Cowork เท่านั้น
